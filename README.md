# linger

Keep your apps alive across logouts, reboots and crashes — with a tiny Rust CLI
that turns a simple config into `systemd --user` units.

Built for minimal X setups (twm, etc.) where you don't want a full desktop
session manager and don't care about restoring window positions.

## Why

`systemd --user` is already the supervisor: it tracks processes with cgroups,
restarts them when they die, and starts them at boot. What's missing is a nice
way to describe *which* apps to keep alive and to carry the X session
environment (`DISPLAY`, `XAUTHORITY`, `DBUS_SESSION_BUS_ADDRESS`) into units
that start before you log in.

`linger` is that layer. It generates the units, enables them, and enables
`loginctl enable-linger` so your user manager outlives logout.

```
config.toml ──> linger sync ──> ~/.config/systemd/user/linger-*.service
                                        │
                                        ▼
                              systemd --user (cgroups + D-Bus)
                                        │
                                        ▼
                                   your apps
```

There are no shell scripts in the generated units. The only helper is
`linger wait-for-x`, also written in Rust.

## Install

```bash
cd ~/Projects/Linger
./install.sh                       # installs to ~/.local/bin/linger
PREFIX=/usr/local ./install.sh     # system-wide (needs root)
./install.sh --init                # install and run `linger init`
```

Or manually:

```bash
cargo build --release
install -Dm755 target/release/linger ~/.local/bin/linger
```

Make sure the install directory is in your `PATH`.

## Quick start

Run this **from inside your X session**, once:

```bash
linger init
```

That creates `~/.config/linger/`, writes an empty config, snapshots your
session environment, and enables lingering for your user.

Then add apps:

```bash
linger add kitty /usr/bin/kitty --app dev
linger add nautilus /usr/bin/nautilus --restart on-failure
linger add lafd ~/Projects/linux-audio-focus-daemon/target/release/lafd --no-wait-for-x --env RUST_LOG=info

linger up
```

Check everything:

```bash
linger list
linger status kitty
linger doctor
```

## Commands

| Command | What it does |
|---|---|
| `linger init` | One-time setup: dirs, config, env snapshot, `enable-linger` |
| `linger add <name> <cmd> [args...]` | Add an app, write its unit, enable and start it |
| `linger remove <name>` | Remove it from config, stop, disable, delete unit |
| `linger list` | Show apps with active/enabled state |
| `linger sync` | Regenerate all units, `daemon-reload`, enable them |
| `linger up` | `sync` + start (or restart) everything |
| `linger down` | Stop and disable everything (keeps config) |
| `linger status <name>` | Pass through to `systemctl --user status` |
| `linger env` | Re-capture `DISPLAY` / `XAUTHORITY` / DBUS from current session |
| `linger doctor` | Verify systemd, lingering, config, env and DISPLAY |
| `linger wait-for-x` | Internal helper used by `ExecStartPre` |

## Config

Lives at `~/.config/linger/config.toml` (see `config.example.toml`):

```toml
[[apps]]
name = "kitty"
command = "/usr/bin/kitty"
args = ["--app", "dev"]
restart = "always"      # always | on-failure | never
restart_sec = 3
wait_for_x = true
after = ["display-manager.service"]

[[apps]]
name = "lafd"
command = "/home/you/Projects/linux-audio-focus-daemon/target/release/lafd"
restart = "always"
wait_for_x = false
env = ["RUST_LOG=info"]
```

After editing it by hand, run `linger up` (or `linger sync` to avoid starting
apps immediately).

Session-wide variables go in `~/.config/linger/env.conf`, which is generated
by `linger env`. Refresh it after starting a new X session (new display number
or Xauthority cookie).

## Generated unit

```ini
# Generated by linger. Edit ~/.config/linger/config.toml, then run `linger sync`.
[Unit]
Description=linger: kitty
After=display-manager.service

[Service]
Type=simple
EnvironmentFile=/home/you/.config/linger/env.conf
ExecStartPre=/home/you/.local/bin/linger wait-for-x
ExecStart=/usr/bin/kitty --app dev
Restart=always
RestartSec=3

[Install]
WantedBy=default.target
```

## How each failure mode is covered

| Event | Behaviour |
|---|---|
| App crashes | `Restart=always` / `on-failure` brings it back after `RestartSec` |
| You log out | `loginctl enable-linger` keeps the user manager (and apps) alive |
| Reboot | Units are enabled, so they start at boot and wait for X via `ExecStartPre` |
| twm dies/restarts | Apps are independent of the window manager |

## Layout

```
src/
  cli.rs       clap command definitions
  config.rs    TOML config model + validation
  envfile.rs   capture and render systemd EnvironmentFile
  unit.rs      systemd unit renderer
  systemd.rs   systemctl/loginctl wrappers (the only systemd-facing layer)
  wait.rs      X readiness polling
  main.rs      command dispatch
```

`systemd.rs` is deliberately isolated: replacing the `Command` calls with a
zbus connection to `org.freedesktop.systemd1.Manager` later only touches that
file.

## Caveats

- Apps that don't cooperate with X re-parenting may behave oddly if twm is
  killed, but they keep running.
- `linger env` must be rerun if your X server restarts with a different
  `DISPLAY` or `XAUTHORITY`, otherwise `wait-for-x` will time out.
- GUI apps that need a D-Bus session bus need `DBUS_SESSION_BUS_ADDRESS` in the
  env file; `linger env` captures it when run from a logged-in session.
- This manages process lifetime, not application-internal state. Browser tabs,
  editor undo history, etc. are up to the app itself.
